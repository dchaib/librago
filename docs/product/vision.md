# Product vision

## Problem

Managing several library accounts across multiple library networks can become tedious and error-prone.

A person managing library activity for several family members may otherwise need to sign in to multiple accounts and portals just to understand what is borrowed, what must be returned soon, what is reserved, what is ready for pickup, and where an item is available.

The primary pain point for Librago is avoiding missed return deadlines.

## Vision

Librago provides a unified, family-oriented view of library activity across multiple accounts and library networks.

Its primary purpose is to help answer:

> What requires my attention, and what should I return, collect, renew, or reserve next?

## Target user

The initial target user is one person managing several library accounts for a household.

The default perspective is family-wide rather than account-centric.

## Product priorities

1. Avoid forgetting to return a borrowed item.
2. Avoid missing the pickup deadline of an available reservation.
3. Know what should be returned or collected before going to a library.
4. Find the easiest way to obtain a given item.
5. Renew or reserve items without navigating through each external portal.
6. Help continue series, especially by identifying and suggesting the next volume.

## Convenience and preferences

Availability alone is not always enough to decide where to obtain an item.

Librago may eventually take user preferences into account when ranking or suggesting options.

Preferences may exist at several levels, for example:

- preferred library networks;
- preferred or favorite libraries within a network;
- preferred pickup locations;
- practical convenience of transfer, pickup, or return.

The exact preference model is intentionally left open until search and reservation features are closer to implementation.

## Language

Repository documentation and code are written in English.

The application user interface is primarily intended to be in French.
